# 1000 张图库实测与界面体验优化（2026-10-29）

## 结论

在 1000 张合成图库（ComfyUI + Qwen-Image 2.1，`bench/data/qwen-photo-library`）上做了一轮「先测、再改、再测」：先在真实服务端与真实模型上逐页截图与跑评测，找出界面与算法问题，修复后在合并后的 main 上全量复测。本轮合入 #100–#110，共 11 个 PR。

- **界面**：分组网格从每屏约 3 张提升到 13 张以上；网格可用键盘 Tab 进入并用方向键浏览，读屏能读出星级/旗标/色标；错误提示全部本地化；浅色主题的语义色、焦点环与控件边框达到对比度要求（124 组颜色由 `npm run contrast` 守门）；弹层统一焦点管理；手机端键盘不再遮挡输入框。
- **功能**：中文自然语言搜索在应用内的召回从 0.086 提高到 0.606（此前多数中文查询在应用里**返回空**）；模糊误报从 113 降到 24（精确率 0.23 → 0.63，召回 0.48 → 0.58）；「说话中」召回 48% → 74%；多设备时间对齐的「全部采纳」不再采纳错误估计。
- **打包缺陷**：桌面打包脚本会把旧 ABI 的原生 quality 库打进安装包，导致 worker 静默回退到 Python，分析慢约 50%（#110 修复）。

仍是合成图库上的证据，不替代真实相机/手机照片、真机与读屏软件验收；见文末「仍未验收」。

## 环境与数据

- Windows，i7-13700K、64 GB、RTX 4090；通过 Oracle 桥接以普通账户运行。ONNX Runtime 的 CUDA 可用（standard 分析走 GPU）；wgpu 渲染在非交互会话里找不到适配器，GPU 渲染耗时未测。
- 照片副本与独立目录库都在 `bench/data/verification-2026-10-29/`（`photos*`、`catalog2` 基线、`catalog-final` 终测、`catalog-native` 原生库复测）；原图库未改动。下文证据路径都相对这个目录。
- 截图脚本 `web/scripts/ux-audit.mjs`：桌面 1440×900、笔记本 1280×720、手机 390×844 三种尺寸，逐页及主要状态（检查器、单张、组、对比、命令面板、帮助、筛选弹层、时间线、右键菜单、导出、助手、搜索、人物、编辑、最佳表情、风格、设置）共 72 步，记录页面异常、5xx、横向溢出、小于 24px 的点击目标与无名按钮，并检查键盘焦点。

## 复测结果（main 0ae288ca，即 #109 合入后；#110 的效果用本地重建原生库验证）

门禁（`final/`）：`cargo fmt --check`、`cargo clippy --workspace --all-targets -D warnings`、`cargo test --workspace`（961 通过，0 失败）、release 构建；web lint、tsc、vitest 全部通过、`npm run contrast`（124 组通过）、`pnpm build`；worker ruff 与 pytest（319 通过、4 跳过）。第一次 clippy 因 `ort-sys` 解压预编译库时文件被占用（os error 5）失败，单独重跑通过，不是代码问题。

分析（standard，1000 张，`final/analysis*.log`）：原生库 87.9 s（11.4 张/秒）；旧库被拒、回退 Python 时 134.4 s。两次的问题计数与评测结果完全一致。

问题标签（`eval-library`，前 → 后）：

| 标签 | TP / FP / FN 前 | 后 | 精确率 | 召回 |
|---|---|---|---|---|
| 模糊 | 34 / 113 / 37 | 41 / 24 / 30 | 0.23 → 0.63 | 0.48 → 0.58 |
| 说话中（bad_expression） | 24 / 21 / 26 | 37 / 17 / 13 | 0.53 → 0.69 | 0.48 → 0.74 |
| 欠曝 | 7 / 4 / 5 | 7 / 3 / 5 | 0.64 → 0.70 | 0.58 |
| 闭眼、过曝、噪点、倾斜 | 不变 | 不变 | 0.88 / 1.00 / 0.48 / 0.00 | 0.98 / 0.92 / 0.92 / 0.00 |

人物聚类不变：单人照片成对 F1 0.948、纯度 0.980；合照找到 1050/1085。

搜索（应用默认参数，`final/search-*.txt`）：

| 语言 | R@20 前 → 后 | P@20 前 → 后 | 返回空的查询 | 不存在的概念被标「相关性较低」 |
|---|---|---|---|---|
| 英文 | 0.377 → 0.733 | 0.880 → 0.631 | 2/20 → 0/20 | 9/10 |
| 中文 | 0.086 → 0.606 | 0.375 → 0.499 | 11/20 → 0/20 | 10/10 |

代价：图库里没有的东西不再返回空，而是返回约 30 张最接近的照片并加上提示。中文仍失败：「一碗热腾腾的面条」「红色的鸟居」「草坪上的婚礼」（婚礼英文也失败）。

时间对齐（`eval-time-align --true-clocks`，200 次）：真实设备（同一时钟）错误估计 155 → 1；模拟双机 5 秒内 137 → 187/200；置信度 ≥ 0.5 的 176 个估计 0 个错误。

接口模块（`final/api/run.log`）：目录、媒体、评分标签、集合与预设、编辑渲染、导出、文件监听/重定位/淘汰、备份恢复 8 项全部通过（导出与文件项需先把输出目录加入允许的根目录 `PATCH /api/settings {"roots": [...]}`，10-14 的脚本失败即因此）。

界面（`final/ux/`）：72 步全部通过，无页面异常、5xx 或横向溢出；键盘步骤 Tab 到网格、两次下方向键后 `aria-activedescendant` 指向存在的格子且焦点环可见。

## 仍未验收 / 已知问题

- 全部是合成 JPEG：真实相机/手机照片下的模糊比例 0.85、`jawOpen` 0.06、搜索上限 0.095（中文两侧余量约 0.005）、人物封面评分都需要真实照片复核。
- 读屏软件（NVDA/VoiceOver/TalkBack）、真机手机键盘避让、触屏手势没有实测；可访问性只做了源码审查、对比度计算与浏览器自动化检查，不代表合规。
- 倾斜检测在本库仍是 TP 0 / FP 24（本库不是旋转标定集）。
- 人物页：一个狗的聚类会作为「人物」出现（检测层面的问题，可手动隐藏）；两个只有背光照片的人物封面仍偏暗。
- 分组视图下搜索结果按场景排列，不按相关度；需要按相关度看时可切到平铺。
- 助手（LLM）本轮没有重跑 20 条指令；GPU 渲染耗时、安装包、Android 未测。
