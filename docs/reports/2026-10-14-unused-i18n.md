# Unused translation keys (2026-10-14)

## Method

1. Every leaf key path in `web/src/i18n/en.ts` was listed (object nesting joined with dots). `zh-CN.ts` was checked for the same key set; the two files were in parity before and after the change.
2. Usage sources: every `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs` file under `web/` (excluding `node_modules`, `dist`, and the dictionaries in `web/src/i18n/`, but including `web/src/i18n/i18n.test.ts`).
3. A key is USED when its full dotted path appears in the source text with no letter, digit or underscore immediately before or after it (a conservative match, so a key inside a longer dotted string also counts).
4. Dynamic lookups: every `${...}` template and every `'literal' +` concatenation in `web/src` whose static part ends in `.` or `_` was collected as a prefix; every key starting with such a prefix is USED. Non-dotted static parts were also reviewed. Template sites with no static part (for example `` `${BASE}/thumb/...` ``) are URL builders, not translation lookups.
5. Plural suffixes (`_zero`, `_one`, `_two`, `_few`, `_many`, `_other`, `_plural`) count as used when their base key is used.
6. The key families enumerated in `web/src/i18n/i18n.test.ts` (`families`) were evaluated and count as used (368 keys).
7. Repository-wide search (Rust crates, `ai-worker`, `apps`, `docs`) for the candidate names, to catch keys that the backend emits.

Kept.
