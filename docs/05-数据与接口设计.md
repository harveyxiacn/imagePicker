# 05 数据模型与接口设计

## 1. 数据库（SQLite，catalog.db）

PRAGMA：`journal_mode=WAL`、`synchronous=NORMAL`、`foreign_keys=ON`、`mmap_size=268435456`。迁移是 `crates/ip-core/src/db.rs` 中按序追加的 `MIGRATIONS` 数组（`PRAGMA user_version`，**当前为 17**；已发布的迁移只追加、不修改；库的版本高于程序时拒绝打开）。没有使用 `refinery`。

> **本节 SQL 是概念模型**，与实现的差异已在各表注释中标出；权威定义是 `MIGRATIONS`。实际共 24 张业务表：`root_folder`、`device`、`event`、`scene`、`burst`、`photo`、`session`、`session_photo`、`task`、`analysis`、`person`、`face`、`edit_version`、`preset`、`beauty_geometry`、`smart_collection`、`preference_label`、`taste_state`、`taste_score`、`photo_tag`、`xmp_state`、`catalog_meta`、`session_stat`、`session_device_offset`。设计中的 `history`、`tag`、`tag_link` **不存在**（见下）。

完整性与备份：启动后后台 `PRAGMA quick_check`；每天 `VACUUM INTO` 到 `<数据目录>/backups/catalog-*.db`（保留 7 份）；文件打不开时移到 `backups/corrupt-*.db` 并以空目录库启动，由用户从备份恢复（`GET /api/catalog`、`POST /api/catalog/backup`、`POST /api/catalog/restore`，见 [api-contract-m6 §F](api-contract-m6.md)、[02 §8](02-架构设计.md#8-安全与隐私)）。

日志与崩溃记录：`<数据目录>/logs/imagepicker-*.log`（按日 / 5 MiB 滚动，14 天、40 MiB 封顶）与 `<数据目录>/crashes/`（Rust panic 的 `crash-*.txt`、AI worker 的 `worker-*`）；设置页「诊断」导出的诊断包（`POST /api/system/diagnostics`）只含脱敏的文本，不含照片、缩略图、人脸数据、目录库和照片路径（见 [api-contract-m6 §G](api-contract-m6.md)）。

```sql
  taken_at_offset_min INTEGER,            -- 拍摄地 UTC 偏移（分钟，v3），仅用于显示本地时刻
  taken_at_raw INTEGER, device_id INTEGER REFERENCES device(id),

  gps_lat REAL, gps_lon REAL,
  burst_id INTEGER REFERENCES burst(id),
  rank_in_burst INTEGER,
  dup_group_id INTEGER, dup_kind TEXT,    -- v13：重复组（组内最小照片 id，整个目录库）/ exact | near
  -- 用户决定（永远优先）
  user_rating INTEGER CHECK(user_rating BETWEEN 0 AND 5),
  flag INTEGER DEFAULT 0,                 -- 1 精选 / -1 淘汰 / 0 无
  color_label TEXT,
  -- AI 建议
  ai_score REAL, ai_rating REAL,          -- ai_rating 允许 0.5 步长展示
  base_score REAL,                        -- 个性化之前的 ai_score（v6）
  issues INTEGER DEFAULT 0,               -- 位掩码：1闭眼 2模糊 4过曝 8欠曝 16倾斜 32路人（bystander）64噪点 128表情欠佳（bad_expression）
  scene_type TEXT,
  thumb_state INTEGER DEFAULT 0,          -- 0 无 1 内嵌 2 网格 3 预览
  analysis_version INTEGER DEFAULT 0,
  has_edits INTEGER DEFAULT 0, edit_hash TEXT,  -- edit_hash：当前编辑栈内容哈希（v5）
  meta_done INTEGER NOT NULL DEFAULT 0,   -- 元数据阶段已完成

CREATE INDEX idx_photo_burst ON photo(burst_id, rank_in_burst);

CREATE TABLE session_device_offset (

                    session_id INTEGER, photo_count INTEGER NOT NULL DEFAULT 0, offset_min INTEGER,

CREATE TABLE scene (id INTEGER PRIMARY KEY, event_id INTEGER REFERENCES event(id), title TEXT, start_at INTEGER);

CREATE TABLE analysis (

  embedding BLOB,                         -- f16 向量（SigLIP 768/1152d）

  tilt_confidence REAL,                   -- 倾斜估计的置信度 0–1（v10）
  aesthetic REAL, iqa REAL, composition REAL,   -- composition：构图分 0–1，评分时由主体框/显著性/倾角算出（v15 起写入，docs/03 §3.1.3）

  scene_scores TEXT,                      -- JSON：8 类场景得分

  explain TEXT,                           -- JSON：分项贡献与理由
  artifacts_dir TEXT                      -- 缓存目录（蒙版、关键点等）
);

CREATE TABLE face (
  id INTEGER PRIMARY KEY,
  photo_id INTEGER REFERENCES photo(id) ON DELETE CASCADE,
  idx INTEGER NOT NULL DEFAULT 0,         -- 在该照片 faces[] 中的位置
  person_id INTEGER REFERENCES person(id) ON DELETE SET NULL,
  person_locked INTEGER NOT NULL DEFAULT 0, -- 用户手动指定（must-link / cannot-link）
  track_id INTEGER,                       -- 连拍组内同一人的轨迹
  bbox_x REAL, bbox_y REAL, bbox_w REAL, bbox_h REAL,  -- 归一化，显示方向
  det_score REAL, embedding BLOB,         -- 512d f16
  eyes_open REAL, smile REAL, gaze REAL, yaw REAL, pitch REAL, roll REAL,
  sharpness REAL, occlusion REAL, expression_score REAL,   -- occlusion 预留，未产生
  is_subject INTEGER, is_bystander INTEGER,   -- is_bystander = 非主体且非人造脸（消除路人的候选）
  artificial REAL,                        -- 0–1：脸在雕像/海报/屏幕上的置信度，≥ 0.55 视为人造（v15，docs/03 §3.1.2）

CREATE INDEX idx_face_person ON face(person_id, photo_id);
CREATE INDEX idx_face_photo ON face(photo_id);

CREATE TABLE person (id INTEGER PRIMARY KEY, name TEXT, cover_face_id INTEGER,
                     hidden INTEGER DEFAULT 0, beauty_profile TEXT,  -- JSON
                     center BLOB, created_at INTEGER,                -- 平均身份嵌入 f16
                     singleton INTEGER NOT NULL DEFAULT 0);          -- 单张照片的主体人物（v7）

CREATE TABLE edit_version (
  id INTEGER PRIMARY KEY, photo_id INTEGER REFERENCES photo(id) ON DELETE CASCADE,
  name TEXT,                              -- 目前恒为主版本；虚拟副本未实现（每张照片只有一条 is_current = 1 的记录）
  stack TEXT NOT NULL,                    -- JSON 编辑栈（见 §2），按收到的原样保存
  hash TEXT NOT NULL,                     -- 编辑栈内容哈希
  updated_at INTEGER, is_current INTEGER DEFAULT 1
);

-- 没有 history 表：评分/旗标/编辑的撤销在前端 store 中完成，助手执行时服务端返回 `undo` 载荷（api-contract-m6）；服务端无 /undo、/redo。

  kind TEXT,                              -- rating | flag
  value REAL,                             -- 评分 1..5 / 旗标 +1 -1
  source TEXT DEFAULT 'patch',            -- 只有 patch（用户亲手）且与照片当前值一致的才参与训练；旧库的 accept_ai 行被忽略（03 §3.3）
  legacy INTEGER DEFAULT 0,               -- v17：1.0 记录的标签
  created_at INTEGER NOT NULL, UNIQUE(photo_id, kind)
);
CREATE TABLE taste_state (id INTEGER PRIMARY KEY CHECK (id = 1), model TEXT, labels_at_train INTEGER, active INTEGER,
                          alpha REAL, holdout_accuracy REAL, base_accuracy REAL, pairs INTEGER, traits TEXT, trained_at INTEGER,
                          -- v17（taste v2）：
                          enabled INTEGER DEFAULT 1, feature_version INTEGER, model_version INTEGER, pending_labels INTEGER,
                          positives INTEGER, negatives INTEGER, metrics TEXT, rescore_pending INTEGER);  -- 个性化模型状态（单行，迁移即建）；metrics = 交叉验证 AUC 与基线等 JSON

                          score REAL NOT NULL, model_version INTEGER NOT NULL);  -- v17：当前风格模型下每张照片的风格分（0..1）；模型变化 / 关闭 / 重置时清空

                   params TEXT, progress REAL, error TEXT, created_at INTEGER, updated_at INTEGER,
                   done INTEGER, total INTEGER, finished_at INTEGER);  -- 任务记录，保留最近 200 条（api-contract-m5 G）；status 含 paused（暂停的分析）；analysis 任务的 params 是运行参数（session_id、profile、photo_ids、force、fallback_lite、started_at、resumes…），重启后据此续跑（api-contract-m2 C.5.2）

CREATE TABLE session (id INTEGER PRIMARY KEY, title TEXT, cover_photo_id INTEGER, created_at INTEGER,
                      root_id INTEGER REFERENCES root_folder(id), import_state TEXT NOT NULL DEFAULT 'ready',
                      recursive INTEGER DEFAULT 1, exclude TEXT);  -- 导入选项（exclude 为 JSON 数组），重新扫描 / 文件监听沿用
CREATE TABLE session_photo (session_id INTEGER, photo_id INTEGER, PRIMARY KEY(session_id, photo_id));  -- RAW companion（photo.pair_id 非空）不在此表：网格、分组、分析只见 JPEG；另有 `sk_*` 排序键副本和 `session_stat` 计数表，见 1.3
CREATE TABLE smart_collection (id INTEGER PRIMARY KEY, name TEXT, query TEXT, created_at INTEGER);  -- query = GET /api/photos 的 URLSearchParams（不含 session_id/cursor/limit）
CREATE TABLE photo_tag (photo_id INTEGER, tag TEXT, PRIMARY KEY(photo_id, tag));        -- 关键词（XMP dc:subject）；没有 tag / tag_link 表
```

### 1.2 向量检索

- 会话规模（≤ 2 万张）：启动时把嵌入载入内存（2 万 × 1152 × f16 ≈ 46MB），暴力余弦 + SIMD，< 5ms。
- 大库（10 万+）：启用 `sqlite-vec` 虚拟表或 HNSW（`hnsw_rs`）索引。

### 1.3 会话派生数据（大会话，迁移 v14）

单会话 10 万张时，网格分页和会话列表都不能再按会话成员数计算。两份派生数据由触发器在写入的同一事务里维护，不需要应用层配合：

```sql
CREATE TABLE session_stat (session_id INTEGER PRIMARY KEY REFERENCES session(id) ON DELETE CASCADE,
  photo_count INTEGER, picked_count INTEGER, rejected_count INTEGER, rated_count INTEGER);
-- session_photo 增加排序键副本（来自 photo.taken_at / file_name / user_rating / ai_score）
ALTER TABLE session_photo ADD COLUMN sk_taken INTEGER, sk_name TEXT, sk_rating INTEGER, sk_ai REAL;
CREATE INDEX idx_sp_taken_asc  ON session_photo(session_id, COALESCE(sk_taken, 9223372036854775807), photo_id);
CREATE INDEX idx_sp_taken_desc ON session_photo(session_id, COALESCE(sk_taken, -9223372036854775807) DESC, photo_id);
CREATE INDEX idx_sp_name   ON session_photo(session_id, sk_name COLLATE NOCASE, photo_id);
CREATE INDEX idx_sp_rating ON session_photo(session_id, COALESCE(sk_rating, -1) DESC, photo_id);
CREATE INDEX idx_sp_ai     ON session_photo(session_id, CAST(COALESCE(sk_ai, -0.001) * 1000000 AS INTEGER) DESC, photo_id);
CREATE TABLE catalog_meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);  -- session_derived_epoch
```

- **计数**：`session_stat` 与 `GET /api/sessions` 的 `photo_count / picked_count / rejected_count / rated_count` 一一对应。计数对象是 `session_photo` 的行，所以 RAW companion（不在 `session_photo`）不计入。触发器覆盖：会话建立、成员加入 / 移除（配对时 `DELETE FROM session_photo`）、`photo.flag` / `photo.user_rating` 变化、照片删除（`BEFORE DELETE` 先解除成员关系）、会话删除（级联）。
- **排序键**：`GET /api/photos` 的 `taken_at / -taken_at / name / rating / ai` 五种排序各有一个索引，表达式与查询里的排序表达式逐字相同，成员直接按页序从索引读出，`LIMIT n+1` 即停，不再访问整个会话。游标语义不变：`(键, photo_id)`，键相同按 `photo_id` 升序，无拍摄时间的照片排在末尾（升序）或最后（降序）。`total` 在没有筛选时读 `session_stat.photo_count`。分页接口只有游标（没有 `offset` 参数），因此对现有客户端没有变化。
- **修复**：`catalog_meta.session_derived_epoch` 与代码里的 `SESSION_DERIVED_EPOCH` 不一致（或被删除）时，下次打开目录会调用 `catalog::rebuild_session_derived` 重新计算两份数据；修改派生数据的定义时递增该常量。一致性测试：`tests_scale.rs`。

## 2. 编辑栈格式（Edit Stack v1）

类型定义的唯一出处是 `crates/ip-render/src/lib.rs` 的 `EditStack` / `Op`（serde；字段名即下面的 JSON 键）。**未知的 `type`（以及 `warp` / `patch` 的未知 `kind`）会被忽略而不报错，缺省字段取默认值**，所以旧栈可被新版读取；但缺少**必填**字段（`crop.rect`、`patch.kind` / `asset` / `rect`、`local.mask` / `adjust`、`lut.file`）时整份栈无法解析。`crates/ip-render/tests/schema.rs` 的解析测试（`parses_doc05_stack_and_ignores_future_ops`、`parses_m4_portrait_ops`、`parses_m5_patch_op`）覆盖下面示例的每一种 op 形状；示例本身（逐字段对照类型定义写成）：

与旧版文档的差别（均以代码为准）：没有 `base`（RAW 显影参数，RAW 只用内嵌预览）；`crop.rect` 必填，`angle` 单位是度、**正值 = 内容逆时针**（`ip-render` 注释），与分析的 `tilt_deg` 符号约定的关系见 03 §6.6；`patch` 必须带 `asset`（不透明资产 id，由 `MaskProvider::patch` 解析）和 `rect`（转正后的归一化 `[x, y, w, h]`），没有 `mask` / `transform` 字段，`kind` 取 `best_take | hair | inpaint | denoise | face_restore | deshine | flyaway`（`deshine` / `flyaway` = 去汗光 / 整理碎发，03 §7.5；`hair` = 换发型，附加字段 `base_face_id` / `source_face_id` / `align` / `warnings` 按原样保存，见 api-contract-m5 H）；`global` 的调整量直接平铺在 op 上（等同 `Adjust`）；`local.mask` 的 `kind` 为 `ai`（`target` ∈ subject / background / sky / person / skin / hair / clothes，可带 `person_id`）、`radial`（`center`、`radius`、`feather`）、`linear`（`start`、`end`）；`lut.file` 是内置 LUT id 或 `.cube` 绝对路径；`level` ∈ `natural | standard | refined`；`id` 字段不在类型里（保存时按原样透传，渲染忽略）。

- 渲染顺序见 [02 §5.3](02-架构设计.md)：补丁（裁剪前）→ 裁剪/旋转 → 形变 → `global` / `local` / `beauty`（按 `ops` 中出现的顺序）→ LUT → 输出锐化。
- 引用人物/蒙版的操作在渲染时**按需重新生成**AI 资产（缓存失效时），因此编辑栈可复制到其他照片：`person_id` 在目标照片中找到同一人物即生效，找不到则跳过并提示。
- 预设 = 编辑栈中不含照片特定资产的子集（`preset` 表；内置预设来自 `builtin_presets()`）。
- 可导出自有 `.ipedit.json` **未实现**。
- 本文档的 JSON Schema 不由代码生成（没有 `schemars` 依赖）；若要机器可读的 schema，应由 `ip-render` 类型派生（待办，见 09 §3 05 行）。

## 3. API（HTTP + WebSocket）

## 4. Core ⇄ AI Worker 协议

WebSocket JSON-RPC 2.0（本地 Worker），地址与令牌由 Core 启动 Worker 时指定（`IP_WORKER_ADDR`、`IP_WORKER_TOKEN`，或 `ai-worker` 命令行参数）。**远程 AI** 不是直连 Worker，而是手机/笔记本经另一台 imagePicker 主机的 `/api/remote/rpc`（HTTP，设备令牌认证，仅 `REMOTE_METHODS` 白名单内的方法，图片只能是已上传文件的 `file:` 引用）调用主机的 Worker，见 [api-contract-m8](api-contract-m8.md)。类型定义在 `crates/ip-worker-client/src/protocol*.rs`，契约见 api-contract-m2/m3/m4/m5/m6。

```jsonc
// 请求
{ "jsonrpc":"2.0", "id": 101, "method": "analyze.batch",

              "analysis_size":1024, "out_dir":"<cache>/analysis", "allow_download": false } }

{ "jsonrpc":"2.0", "id":101, "result": { "items":[{ "photo_id":12,
    "phash":"a3f0…", "sharpness":0.82, "exposure":0.7, "noise":0.05, "quality":{ "tilt_deg":0.4, "tilt_confidence":0.1 },
    "iqa":0.71, "aesthetic":0.64, "scene_type":"portrait",
    "embedding_file":"…/12.emb.f16", "identity_file":"…",
    "faces":[{ "bbox":[…], "eyes_open":0.97, "smile":0.62, … }] }],
    "steps":[…], "skipped_steps":[…], "models":{…}, "warnings":[], "timings":{…} } }
```

| 方法 | 说明 |
|---|---|
| `system.info` / `system.ping` / `system.shutdown` | 硬件、档位（含 `tier_detected`、`tier_overridden`）、已加载模型；存活检查；退出 |

## 5. XMP 侧车互通

- 读：导入时若存在 `IMG_0001.xmp`（或 JPEG 内嵌 XMP），读取 `xmp:Rating`、`xmp:Label`、`xmpDM:pick`/`lr:hierarchicalSubject`、darktable 的 `xmp:Rating`（-1 表示 reject）。
- 写（可配置：关闭 / 仅侧车 / 修改原图 = 侧车 + JPEG 内嵌）：用户评分、色标、旗标（Lightroom 无标准 pick 字段，采用 `xmp:Rating=-1` 表示淘汰的 darktable 约定，并在设置中说明）、关键词、标题。只有「修改原图」模式会改写原图文件，开启需二次确认（`confirm_modify_originals`，见 [api-contract-m6 §C](api-contract-m6.md)）；其他模式不改变原图的任何字节。
- 冲突策略：以最后修改时间为准，冲突时提示用户选择。
- **不写入**编辑栈到第三方格式（各软件不兼容）；可导出自有 `.ipedit.json`。
