# Releasing imagePicker

Rules (docs/06-项目计划书.md section 4): SemVer (`0.<milestone>.<patch>` before 1.0), Conventional Commits,
a `v*` tag triggers the Release build, `CHANGELOG.md` is generated by git-cliff, every artifact ships with a SHA256.

## Cut a release

```sh
git switch main && git pull
scripts/bump-version.sh 0.2.0            # Cargo.toml, Cargo.lock, tauri.conf.json, both package.json, pyproject.toml
git cliff --tag v0.2.0 --output CHANGELOG.md
git add -A Cargo.toml Cargo.lock apps/desktop web/package.json ai-worker/pyproject.toml CHANGELOG.md
git commit -m "chore(release): v0.2.0"      # open a PR if main is protected; the tag must end up on main
git tag -a v0.2.0 -m "imagePicker v0.2.0"
git push origin main v0.2.0
```

`scripts/bump-version.sh` prints these commands for you and never tags or pushes. CI (`version-consistency`) fails if
any manifest disagrees; the release workflow additionally requires the tag to equal the manifest version.

Pushing the tag runs `.github/workflows/release.yml`:

1. `prepare`: verifies versions, generates release notes with git-cliff (`cliff.toml`) for the range since the previous tag.
2. `build` (matrix): Windows x64 (NSIS `.exe` + `.msi`), macOS universal (`.dmg`, arm64 + x64), Linux x64 on
   Ubuntu 22.04 (`.AppImage` + `.deb`, glibc 2.35 baseline). Runs `apps/desktop/scripts/fetch-uv.*` first if it exists.
3. `publish`: gathers installers, writes `SHA256SUMS.txt`, creates a **draft** GitHub Release.

Review the draft (notes, files, checksums, install on at least one platform), then press Publish. After publishing,
update the AUR (below).

### Dry runs

* Actions > Release > Run workflow with `dry_run` ticked (the default): builds everything, uploads
  `release-bundle-dry-run` (installers + `SHA256SUMS.txt` + notes) as a workflow artifact, creates no Release.
* A pull request that touches `release.yml`, `tauri.conf.json`, `bump-version.sh` or `cliff.toml` runs the same dry run.
* Locally: `scripts/bump-version.sh --check v0.2.0`, `git cliff --unreleased --tag v0.2.0 --strip header`.

Pre-releases: use a numeric suffix such as `0.2.0-1` (WiX/MSI rejects non-numeric pre-release identifiers); the Release
is then marked as pre-release automatically.

## Signing (optional; everything works unsigned)

Without secrets, installers are unsigned: Windows SmartScreen warns ("More info > Run anyway"); macOS Gatekeeper blocks
the downloaded app (`xattr -dr com.apple.quarantine /Applications/imagePicker.app` or right-click > Open).
Add secrets under Settings > Secrets and variables > Actions; the workflow detects them and enables the matching step,
no workflow edit needed.

| Platform | Secrets | Notes |
|---|---|---|
| Windows | `WINDOWS_CERTIFICATE` (base64 of the `.pfx`: `base64 -w0 cert.pfx`), `WINDOWS_CERTIFICATE_PASSWORD` | Imported into the runner store; a runtime `--config` override sets `bundle.windows.certificateThumbprint`, SHA-256 digest and a DigiCert timestamp. An EV/OV certificate removes the SmartScreen warning only after reputation builds. For HSM/cloud signing (SignPath, Azure Trusted Signing) replace the step with the vendor's action. |
| macOS signing | `APPLE_CERTIFICATE` (base64 `.p12` Developer ID Application), `APPLE_CERTIFICATE_PASSWORD`, `APPLE_SIGNING_IDENTITY` (e.g. `Developer ID Application: Name (TEAMID)`) | Tauri imports the certificate itself from these env vars. |
| macOS notarisation | `APPLE_ID`, `APPLE_PASSWORD` (app-specific password), `APPLE_TEAM_ID` | Only used when the signing secrets above also exist. |
| Updater | `TAURI_SIGNING_PRIVATE_KEY` (+ `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`) | Generate with `pnpm tauri signer generate -w ~/.tauri/imagepicker.key`. Also needed in the repo (not yet done): set `bundle.createUpdaterArtifacts: true`, add `tauri-plugin-updater`, put the public key and the `latest.json` endpoint (`.../releases/latest/download/latest.json`) in `plugins.updater`. `.sig` files are already collected into the Release. |

## AUR (CachyOS / Arch)

Two packages live in `packaging/aur/`: `imagepicker-bin` (repackages the release `.deb`) and `imagepicker` (builds the tag
from source with cargo + pnpm).

```sh
packaging/aur/update.sh 0.2.0     # after the Release is published: rewrites pkgver, sha256sums, .SRCINFO
cd packaging/aur/imagepicker-bin && makepkg -f && namcap PKGBUILD *.pkg.tar.zst   # on an Arch/CachyOS box
```

Then copy each directory into its own AUR git repo (`ssh://aur@aur.archlinux.org/imagepicker-bin.git`, `.../imagepicker.git`),
commit and push. First-time AUR registration needs an AUR account and SSH key.

## Nightly

`.github/workflows/nightly.yml` (02:17 UTC + manual) runs all test suites on three OSes and the perf scripts
(`ip-imaging --example bench_thumbs -- --synth 100`, `ip-render --example bench_render`); outputs are uploaded as
`perf-*` artifacts. It never publishes.
